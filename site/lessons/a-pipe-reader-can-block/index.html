A pipe reader can block

Follow a reader waiting for a producer to supply a byte.

Compiler and kernel run locally.
Your source stays in this browser.

An empty pipe with an open writer is not at EOF. Its reader can block: the kernel pauses that process until the condition can change, letting other processes run.

The parent’s supplied sleep(3) asks the kernel to wait for timer ticks before writing. These are guest timer events, not browser milliseconds. It gives the child an opportunity to reach an empty-pipe read; the scheduling chapter will explain sleep in more detail.

piperead sleeps on a channel associated with the read counter. A writer wakes readers after supplying data. The loop checks the condition again after waking; waking is a reason to retry, not a guarantee that a byte belongs to this reader.

C reminder: passing a variable’s address

&ch supplies the address of a char variable so read can fill that byte in the caller. The return value separately reports how many bytes were read. Use a count of one for this single-char destination; a larger count would run past it.

char ch = 0;
int n = read(fd, &ch, 1);
