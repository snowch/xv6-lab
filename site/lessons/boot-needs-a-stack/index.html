C needs a stack before it can run

Follow the initial per-hart stack calculation in the entry assembly.

Ordinary C calls need a stack for saved registers and local values. Before calling start, entry.S loads the address of stack0, computes a per-hart slice and installs its top in the stack-pointer register sp.

Each slice has 4096 bytes. The calculation uses hartid + 1 because a stack grows down from the top of its slice. For hart 0, the top is stack0 + 4096 and the bottom is stack0.

The supplied C observation repeats that source calculation using the real stack0 address and current hart ID. Its result is an offset from the array’s base, not a measurement of the live sp register. Later process kernel stacks are separate allocations; they do not reuse this initial boot stack.

C reminder: addresses and integer casts

In this RV64 kernel, uint64 holds 64-bit values, including its address values. The cast converts a pointer to that integer type for a byte-offset calculation. Adding 4096 to this integer advances by 4096 bytes; adding to a typed pointer would instead count its element size. This calculation does not allocate storage or change the CPU’s stack pointer.

uint64 base = (uint64)stack0;
uint64 top = base + 4096;
int offset = (int)(top - base);
