C needs a stack before it can run

Follow the initial per-hart stack calculation in the entry assembly.

Compiler and kernel run locally.
Your source stays in this browser.

Ordinary C calls need a stack for saved registers and local values. Before calling start, entry.S loads the address of stack0, computes a per-hart slice and installs its top in the stack-pointer register sp.

Each slice has 4096 bytes. The calculation uses hartid + 1 because a stack grows down from the top of its slice. For hart 0, the top is stack0 + 4096 and the bottom is stack0.

The supplied C observation repeats that source calculation using the real stack0 address and current hart ID. Its result is an offset from the array’s base, not a measurement of the live sp register. Build and find an offset of 4096. Later process kernel stacks are separate allocations; they do not reuse this initial boot stack.

C reminder: pointer arithmetic and indexing

p[i] means *(p + i). Adding one to a char pointer advances one byte; other pointer types advance by their element size. Keep accesses within the live allocated region. Moving a pointer does not allocate more memory.

char *next = p + 1;  // the next char address
p[0] = 17;           // write through the pointer

One small experiment
