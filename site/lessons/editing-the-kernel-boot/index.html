The kernel boots before user programs

Change the real kernel boot function and distinguish boot output from program output.

Compiler and kernel run locally.
Your source stays in this browser.

The first six chapters followed operating-system behaviour from user programs. We now revisit it inside the kernel. Start with boot: preparing the machine and kernel data before any user program runs.

The RISC-V kernel image names _entry as its entry point. Assembly in entry.S prepares a stack and calls start. That C function arranges supervisor-mode execution and transfers control to main. This kernel main is different from the main in a user program.

The editor contains the actual main from this build. Its calls form an ordered initialization sequence: console, memory, processes, traps, devices, filesystem caches, then the first user process. Finally scheduler takes control. The lab runs one hart, a RISC-V hardware thread; the other-hart branch remains in the source but is not exercised here.

Build the starter. Find xv6 kernel is booting before init: starting sh and the workbench program’s greeting. Your edit replaces kernel main itself. It does not change the user program.

C reminder: reading a small C program

main is the program’s entry function. Statements end with semicolons, and braces group a function or branch body. In printf, %d formats an integer and \n starts a new line.

int n = 3;
printf("n=%d\n", n);
