The shell composes kernel interfaces

Build redirection with fork, descriptors and exec.

Compiler and kernel run locally.
Your source stays in this browser.

The shell is a user program that combines kernel interfaces. It does not need a special “run this command with redirection” syscall. A child closes descriptor 1, opens the output file into the lowest free slot, and execs the requested program.

The open descriptor survives exec. echo writes to its ordinary stdout, which now names the file. The parent retains its own console descriptors and waits for the child before opening the completed output.

This program builds that composition directly, without a parser. Build to read kernel from the actual redirected file, then change the echo argument to source. The matching runcmd code shows the same descriptor manipulation in xv6’s real shell. Earlier pipe lessons supply the parallel composition used by its PIPE case.

C reminder: arrays used as output arguments

int p[2] reserves two integer elements. Passing p to pipe supplies the array’s starting address, so the function can fill p[0] and p[1]. They are integer handles, not pointers to the pipe’s bytes.

int p[2];
if (pipe(p) == 0) { /* use p[0] and p[1] */ }
