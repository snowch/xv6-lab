fork inherits the pipe ends

Connect parent and child while closing their unused ends.

Compiler and kernel run locally.
Your source stays in this browser.

A pipe created before fork is accessible to both processes. Fork copies descriptor references, so their descriptors connect to the same kernel pipe rather than independent byte buffers.

The child reads and closes its unused write end. The parent writes and closes its unused read end. After writing, the parent closes its writer and waits for the child.

The child reads the data and then checks EOF. Its own unused writer must be closed too: retaining any writer reference would keep that second read waiting. Every process must close the ends it does not need.

C reminder: arrays used as output arguments

int p[2] reserves two integer elements. Passing p to pipe supplies the array’s starting address, so the function can fill p[0] and p[1]. They are integer handles, not pointers to the pipe’s bytes.

int p[2];
if (pipe(p) == 0) { /* use p[0] and p[1] */ }
