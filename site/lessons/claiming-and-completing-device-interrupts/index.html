The interrupt controller identifies a device

Observe real PLIC claims and completions for disk and UART interrupts.

Compiler and kernel run locally.
Your source stays in this browser.

A supervisor external interrupt says that some external source needs attention. The PLIC supplies the device ID through a claim. xv6 routes UART ID 10 to uartintr and VirtIO ID 1 to virtio_disk_intr. After servicing a nonzero claim, it writes a completion so that source can interrupt again.

This edited unit contains the real devintr and a small lab hook. The supplied program calls getpid to arm tracing, performs disk and console I/O, then calls it again to disarm before the shell prompt. Tracing is capped at two matched events, so observing UART interrupts cannot create an endless trace of its own output.

Build and find claimed irq=1 followed by completed irq=1. The values come from the actual controller claim, not a requested file’s descriptor number. Changing the filter selects UART events while the same claim/service/complete protocol runs.

C reminder: static state shared by callbacks

A file-scope static variable has one storage location for this compiled kernel unit and starts at zero. Its value persists between function calls in this VM, so a probe can arm an interrupt observer and later disarm it. An ordinary local variable is separate for each call. A fresh VM resets this state independently of the source draft saved in your browser.

static int watching;
watching = !watching;  // toggle between 0 and 1
