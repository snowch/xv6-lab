Exec establishes the entry stack

Change the real saved entry stack pointer and observe the ABI alignment.

The RISC-V application binary interface (ABI) specifies the machine state that compiled programs expect. At program entry it requires the stack address to be a multiple of 16. exec rounds its argument placements accordingly, records argv in a1 and puts the final entry stack pointer in the trapframe.

It also allocates two stack-area pages and clears user access on the lower one, creating the guard page studied earlier. The usable stack and the argument vector are related parts of the new image, but a1 and sp are distinct saved values.

The editor contains the actual complete exec function. The printed entry stack alignment is the remainder after dividing its address by 16. The variation deliberately misaligns the entry pointer only for workbench. This small integer-only test can still run, but that does not relax the ABI contract; code may depend on its required alignment. Init and shell entry pointers remain normal in this fixture.

C reminder: addresses and integer casts

In this RV64 kernel, uint64 holds 64-bit values, including its address values. The cast converts a pointer to that integer type for a byte-offset calculation. Adding 4096 to this integer advances by 4096 bytes; adding to a typed pointer would instead count its element size. This calculation does not allocate storage or change the CPU’s stack pointer.

uint64 base = (uint64)stack0;
uint64 top = base + 4096;
int offset = (int)(top - base);
