exec replaces the program

Run another executable while keeping the same process identity.

Compiler and kernel run locally.
Your source stays in this browser.

fork created a process. loads a program into the process that calls it. On success, the old program’s memory and starting point are replaced. The process keeps its PID.

The example first prints its PID. It then requests xv6’s existing echo executable. args is a list of argument strings ending with a null pointer: echo’s name, its message, then 0. echo prints the message and exits.

A successful exec does not return to the following printf. Compare the PID printed before exec with the kernel PID captured at process exit, after echo has run. The same process ran both programs.

C reminder: arrays of string pointers

args is an array whose elements point to strings. The final 0 is a null pointer marking the end of the argument list. Each string also has its own zero-byte terminator; these are two different uses of zero.

char *args[] = {"echo", "hello", 0};

What this shows

        
A process is not tied to one program forever. exec replaces its program; it does not create a second process.
