A device register is accessed through an address

Read real UART configuration and status registers through MMIO.

The kernel maps the UART’s physical register region into its address space. Accessing a byte at UART0 plus a register offset invokes the emulated device, rather than reading ordinary RAM. volatile keeps the C access present; it does not by itself create a device mapping.

Offset 3 is the line-control register. uartinit leaves it configured for eight-bit characters with its low two bits equal to 3. The probe shows the register setting in this emulated device.

Offset 5 is the line-status register, which describes different state. In this supplied run, the command’s input has already been consumed; its low receive-ready/error bits are zero. Register offsets and bit meanings are part of the device interface, so the same numeric mask must be interpreted in the selected register’s context.

C reminder: a pointer to volatile bytes

volatile unsigned char *reg points at a byte whose accesses the compiler must preserve. *reg reads that byte; the pointer cast alone performs no read. The address and the kernel’s mappings give it its device meaning. volatile does not create a mapping, grant permission or provide a lock.

volatile unsigned char *reg = (volatile unsigned char*)address;
int bits = *reg & 3;
