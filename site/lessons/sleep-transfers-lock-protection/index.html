Sleep transfers protection before releasing a condition lock

Observe the overlap that prevents a lost wakeup.

Compiler and kernel run locally.
Your source stays in this browser.

A timed sleeper checks ticks while holding tickslock. To block, sleep must release that condition lock so the timer can update ticks. Simply releasing it and then announcing sleep would leave a gap: a wakeup could occur before the process becomes visible as sleeping.

For a different condition lock, sleep first acquires p->lock and only then releases the caller’s lock. wakeup must acquire that same process lock before examining its state. The overlap closes the gap between the condition check and publication of the sleeping state.

The editable sleep observes the condition lock just before releasing it; the process lock is already held. Build and expect 1. Move the observation after release(lk) to see 0. After rescheduling, sleep clears the channel, releases p->lock and reacquires the original condition lock before returning to the caller’s condition loop.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
