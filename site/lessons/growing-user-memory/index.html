sbrk grows the process memory

Request more user memory and interpret the old break returned by sbrk.

Compiler and kernel run locally.
Your source stays in this browser.

A process has a current end to its allocated user memory, often called its break. asks xv6 to change that end by n bytes. On success it returns the old end, where newly added memory starts.

sbrk(0) asks for no change and returns the current break. The example remembers that address, requests 4096 bytes, then writes and reads a byte in the new area. It checks the failure value (char*)-1 before using the result.

This pinned xv6 eagerly allocates memory during sbrk. Growing a process is a kernel operation, unlike declaring another C pointer variable.

C reminder: pointer arithmetic and indexing

p[i] means *(p + i). Adding one to a char pointer advances one byte; other pointer types advance by their element size. Keep accesses within the live allocated region. Moving a pointer does not allocate more memory.

char *next = p + 1;  // the next char address
p[0] = 17;           // write through the pointer
