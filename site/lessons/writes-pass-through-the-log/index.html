Writes pass through filesystem transactions

Follow a regular-file write through the filesystem and verify its bytes.

A regular-file write passes from the descriptor’s open-file object to the inode and block layer. xv6 records changed disk blocks in a log, or journal, so updates can be committed in an ordered way.

In the excerpt, begin_op reserves room for a filesystem operation. writei changes inode data, and end_op participates in committing the logged changes. A large write is split into bounded chunks, so one write syscall can involve several transactions.

The program writes a known byte pattern, closes the file, clears its C buffer, and reads the file back. The static buffer is stored in the program’s data area rather than its small user stack. This experiment verifies the running write/read path; each new run starts with a fresh guest filesystem.

C reminder: array storage and compile-time sizes

enum supplies an integer constant usable as an array size. A static local array has storage lasting for the process, rather than living in this function’s call stack. static does not make user memory shared between separate processes or preserve it across a fresh run.

enum { N = 6000 };
static char data[N];
