The trap cause selects a handling path

Observe a user ecall’s cause before enabling nested kernel interrupts.

A trap can be a synchronous exception or an interrupt. A user ecall is a deliberate synchronous request, identified by scause value 8. usertrap distinguishes that path from device interrupts and unexpected user faults.

The editable function is now the actual usertrap. Its observation runs after saving the user PC but before intr_on. That position matters: a later interrupt can overwrite trap-related CPU registers, so a handler must preserve the state it needs first.

Both getpid and write enter with cause 8. Their saved a7 values identify which operation was requested. User printf can issue many write calls, so several observations are expected.

C reminder: bit masks and short-circuit checks

The bitwise & operator selects flag bits. A selected flag can have a value such as 16, so compare with zero when you want a printed 0 or 1. Logical && evaluates its right side only if the left side is true; entry && (*entry & PTE_V) therefore avoids dereferencing a null pointer.

int user = (flags & PTE_U) != 0;
int valid = entry && (*entry & PTE_V);
