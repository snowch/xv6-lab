Timer interrupts advance a kernel counter

Connect the machine timer path to xv6’s software tick counter.

Compiler and kernel run locally.
Your source stays in this browser.

A timer interrupt lets the OS regain control without a user program requesting a syscall. In this kernel, timerinit programs the machine timer. timervec handles that machine-mode interrupt, schedules the next one, and raises a supervisor software interrupt. devintr recognizes that forwarded event and calls clockintr.

The editable clockintr is the actual kernel routine: it updates ticks under tickslock and wakes processes waiting on that counter. The supplied user program samples uptime until the counter changes. With one runnable test program in this small fixture, observe an increment of 1.

Changing the increment changes logical kernel time, including what timed sleepers observe. It does not measure browser speed. General programs can miss counter updates between samples, so elapsed-time code should use bounds rather than assume every observed difference is exactly one tick.

C reminder: a loop that checks after its body

do ... while runs its body at least once, then repeats while the condition is nonzero. Here each iteration stores a fresh counter sample in after. The semicolon after while is part of this C syntax; the comparison == tests equality without assigning.

do {
  after = uptime();
} while (after == before);
