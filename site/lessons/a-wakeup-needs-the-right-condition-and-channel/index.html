A wakeup needs the matching channel

Observe that changing a condition does not itself wake a sleeping process.

Compiler and kernel run locally.
Your source stays in this browser.

A sleep channel is an identity, commonly an address. wakeup marks processes sleeping on exactly that channel RUNNABLE; it is not a stored token. The shared condition records whether work may proceed, and a loop rechecks it under the condition lock.

The supplied child calls the edited getpid hook first and waits for ready. Its parent sleeps briefly, calls the hook to set ready under the same lock, and wakes the matching channel. Build and expect waiter status=0. sleep’s acquire-before-release handoff prevents a notification from falling between the condition check and publication of the sleeping state.

Set MATCH to 0. The condition becomes true but the notification targets another address, so the child remains sleeping. The parent’s bounded cleanup kills it after two further ticks; the real exit status becomes -1. A notification and a condition are separate parts of one protocol.

C reminder: static state shared by callbacks

A file-scope static variable has one storage location for this compiled kernel unit and starts at zero. Its value persists between function calls in this VM, so a probe can arm an interrupt observer and later disarm it. An ordinary local variable is separate for each call. A fresh VM resets this state independently of the source draft saved in your browser.

static int watching;
watching = !watching;  // toggle between 0 and 1
