The allocator supplies physical pages

Allocate, use and release a real kernel page after allocator initialization.

Compiler and kernel run locally.
Your source stays in this browser.

User sbrk eventually depends on the kernel’s physical page allocator. kinit places available RAM pages, from the end of the kernel image to PHYSTOP, on a free list. Each free page stores the link to the next free page in its own bytes.

kalloc removes one page from that list and returns its kernel address. It can return zero when no page is available. kfree puts a page back; it does not preserve its previous contents for the caller.

The added boot code allocates one page after kinit, writes a byte, reads it back and releases the page before normal boot continues. Build and find 65, the character code for A. This is kernel allocation, unlike sbrk’s user-address-space growth; both ultimately use the same physical memory supply.

C reminder: allocated memory and lifetime

A successful allocation gives you a pointer to live storage. Test for failure before dereferencing it. Releasing the allocation ends your right to use those bytes; a pointer variable can still hold the old address afterwards. xv6’s kalloc and kfree are kernel interfaces introduced in this lesson.

char *page = kalloc();
if (page != 0) {
  page[0] = 65;
  kfree(page);
}
