Dispatch selects a kernel function

Follow the syscall number through the real function-pointer table.

Compiler and kernel run locally.
Your source stays in this browser.

The user stub puts a small number in a7; it does not pass a kernel function address. syscall checks that number’s bounds, checks for a populated table entry, then calls the selected kernel handler. This gives the kernel control over which services are callable.

The table holds function pointers, indexed by the SYS_ constants. The editable function is the actual dispatcher. Its initial selection preserves the normal getpid entry. The supplied user program calls getpid twice with a sleep between them; both results should be the same PID.

Now select sys_uptime for the getpid request. The user stub still sends the same number, but the changed kernel dispatcher runs a different handler. The returned tick counts increase across the sleep. This demonstrates dispatch rather than a change to the stored PID.

C reminder: function pointers and conditional selection

A function pointer names callable code. In uint64 (*table[N])(void), table is an array of N pointers to functions taking no arguments and returning uint64. table[index]() calls the selected function. condition ? yes : no chooses one value without evaluating the other branch.

int selected = condition ? first : second;
uint64 result = table[selected]();
