Shrinking releases user pages

Return allocated memory and observe the restored break.

Compiler and kernel run locally.
Your source stays in this browser.

A negative argument shrinks the process memory boundary. When complete pages fall outside the new boundary, xv6 unmaps and releases them.

The example adds one page, uses it, then removes it. The final break should equal the original break. It deliberately does not read the old pointer after release: that address no longer belongs to this allocation.

The kernel rounds boundaries to whole pages when deciding which mappings to remove. Shrinking by a few bytes within a retained page does not necessarily remove that page.

C reminder: pointer values and memory lifetime

A pointer can keep an address after the memory it referred to has been released. Retaining the value does not keep that allocation alive. The fault lesson deliberately makes an invalid access in a child; volatile does not make that address valid again.

char *saved = p;
// Releasing p’s allocation does not clear saved.
