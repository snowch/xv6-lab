Lesson 8 of 8 in Chapter 10

A disk request completes through an interrupt

Observe the boundary between device completion and a cache buffer becoming valid.

VirtIO communicates through descriptor chains and available/used rings in RAM. The driver describes the request header, data buffer and completion status, publishes the chain and notifies the device. For a read, the device transfers bytes into the buffer.

virtio_disk_rw sleeps while b->disk indicates an outstanding request. The device interrupt handler consumes used entries, clears that flag and wakes the waiter. Returning from virtio_disk_rw therefore marks device completion; bread then sets b->valid so the cache can reuse those bytes.

The edited bread observes that exact boundary for workbench. The supplied program creates a file, causing a cold data-block request, and reads its byte back. The console reports device completion, cache validity and the file byte separately. A later read may be a cache hit and need no new device request.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
