Pipes are byte streams

Observe that read boundaries need not match write boundaries.

Compiler and kernel run locally.
Your source stays in this browser.

Two writes do not create two stored messages in a pipe. They append bytes to a stream. A read asks for up to a byte count, not for one original write.

The example writes AB, then CD. One read can return all four bytes as ABCD. A smaller read would consume only part of the available stream.

In concurrent programs, a read can return fewer bytes than requested. Programs that need a complete message must choose a framing rule, such as a fixed length or a delimiter, and loop over reads.

C reminder: buffers and string terminators

The array has six char elements, initially all zero. Reading at most five bytes leaves the final element zero, so the displayed text remains terminated. read reports bytes obtained; it does not append a C string terminator for you.

char buf[6] = {0};
int n = read(fd, buf, 5);
