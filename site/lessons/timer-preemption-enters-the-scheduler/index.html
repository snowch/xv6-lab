The timer can preempt user computation

Connect a real user timer interrupt to yield without a cooperative syscall.

A CPU-bound user program need not volunteer to yield. A timer interrupt traps into the kernel, devintr identifies it as a timer event, and usertrap calls yield. The kernel can therefore regain scheduling control during a long computation.

This compiled unit replaces the actual usertrap and supplies a temporary getpid lab hook. The first hook call arms a counter; the supplied program then executes a bounded busy loop in user space. The second hook call returns the number of observed timer-driven yields. It intentionally changes getpid’s meaning in this isolated experiment.

The probe prints 1 if it observed one or more such yields. Timer ticks still advance, and kerneltrap has its own preemption path; this edit does not disable all interrupts or all kernel preemption. The count is functional evidence, not a timing benchmark.

Interrupts during kernel execution enter kernelvec, which saves kernel registers on the current kernel stack. kerneltrap saves sepc and sstatus, handles the device, and may yield on a timer while a process is RUNNING. It restores those saved trap registers before kernelvec returns. This kernel-interrupt path does not restore the user trapframe.

C reminder: static state shared by callbacks

A file-scope static variable has one storage location for this compiled kernel unit and starts at zero. Its value persists between function calls in this VM, so a probe can arm an interrupt observer and later disarm it. An ordinary local variable is separate for each call. A fresh VM resets this state independently of the source draft saved in your browser.

static int watching;
watching = !watching;  // toggle between 0 and 1
