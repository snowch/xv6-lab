A kernel context saves a call boundary

Distinguish the small swtch context from a saved user trapframe.

Each process can be suspended while running kernel C code. Its kernel context records enough state to resume the call to swtch: the return address, stack pointer and twelve callee-saved registers. These are the registers an ordinary RISC-V function must preserve for its caller.

Caller-saved registers need no separate entries here. The compiler already saves any live caller-saved values around a function call, often on the kernel stack. swtch returns through that ordinary call boundary. The saved ra supplies the continuation; there is no separate pc field.

A user trap has no such C calling convention boundary. The trampoline therefore saves a much larger trapframe, including user argument and temporary registers. The trapframe’s 36 words include five fields used to enter the kernel.

C reminder: struct members and output arguments

The dot operator reads a member of a struct value. &st passes its address so fstat can fill it. Check that the call succeeded before reading those fields; declaring a local struct alone does not initialise its contents.

struct stat st;
if (fstat(fd, &st) == 0)
  printf("links=%d\n", st.nlink);
