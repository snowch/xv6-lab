A valid mapping still has access permissions

Distinguish validity, user access, writability and executability in actual PTEs.

Compiler and kernel run locally.
Your source stays in this browser.

V says a PTE is valid. U permits user-mode access; W permits writes; X permits instruction fetch. These are separate questions. A valid supervisor mapping can exist in a process’s page table without granting that process user-mode access to it.

The default query examines address 0 in the current user page table. This pinned xv6 allocates ordinary user pages with R, W, X and U set. Build and observe user=1, writable=1 and executable=1. Those are this implementation’s actual permissions.

The kernel’s own text mapping instead allows reads and instruction fetch, while excluding writes and user access. Change the table and address together to inspect that mapping. The experiment reads permission bits; the guard-page lesson later tests a denied access with actual user execution.

C reminder: bit masks and short-circuit checks

The bitwise & operator selects flag bits. A selected flag can have a value such as 16, so compare with zero when you want a printed 0 or 1. Logical && evaluates its right side only if the left side is true; entry && (*entry & PTE_V) therefore avoids dereferencing a null pointer.

int user = (flags & PTE_U) != 0;
int valid = entry && (*entry & PTE_V);
