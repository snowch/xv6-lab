Lesson 5 of 6 in Chapter 14

Boot replays a committed journal

Run xv6’s actual recovery on a prepared interrupted-install image.

This lesson boots an explicitly prepared disk image. README’s home data block contains O. A committed one-entry journal names that block and contains its replacement byte R, as if commit completed but home installation had not. The browser prepares those bytes; it does not perform the recovery.

The editable recover_from_log is xv6’s actual boot routine. read_head loads the committed entry, install_trans(1) copies its recorded data to the home block, and write_head clears the transaction. After boot, the supplied program reads the first byte from README.

Skipping installation leaves the original home byte in place even though the log header is cleared. This disposable fixture isolates one committed data-block update. It demonstrates actual replay, not an emulated physical power cut or every possible storage-failure model.

C reminder: arguments and return values

A call such as f(x) passes an argument to a function. return supplies its result. In a nested call, the inner result becomes an argument to the outer call; assigning the result to a variable can make that easier to read.

int pid = getpid();
printf("reported pid=%d\n", pid);
