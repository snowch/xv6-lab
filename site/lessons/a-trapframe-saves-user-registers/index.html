A trapframe preserves user registers

Read saved user state without confusing it with the kernel’s live registers.

When user code enters the kernel, the CPU does not automatically save every general register. The trampoline’s uservec assembly saves them into the process’s trapframe before using registers for kernel work.

The saved a7 contains the user’s system-call number. The kernel’s live a7 can already mean something else while C functions execute. The observation reads p->trapframe->a7 inside getpid, and compares it with SYS_getpid from the matching header. A printed 1 means the values match.

The saved epc is a user instruction address, not a syscall number. usertrap records it from sepc and advances it past ecall before calling the handler. Selecting epc instead should therefore make this comparison false; it does not change the process’s real PID.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
