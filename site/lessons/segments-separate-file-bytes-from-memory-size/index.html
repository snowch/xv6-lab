A segment’s memory size can exceed its file bytes

Read PT_LOAD sizes from the native BSS fixture.

A loadable program segment names a file offset, a virtual address, a file byte count and a memory byte count. The kernel allocates memsz bytes but copies only filesz bytes. The remaining memory must start at zero.

The supplied native bssprobe contains an uninitialized 4096-byte object in an ELF NOBITS section, which occupies memory without storing those bytes in the file. Its loadable segment therefore has memsz greater than filesz. The probe reads the actual program header from that executable. The probe reports whether the selected size is larger than filesz.

ELF segment flags and the kernel’s chosen page permissions are separate. As the earlier memory chapter showed, this pinned xv6 maps ordinary user allocations RWX; it does not derive per-segment permissions from these ELF flags.

C reminder: struct members and output arguments

The dot operator reads a member of a struct value. &st passes its address so fstat can fill it. Check that the call succeeded before reading those fields; declaring a local struct alone does not initialise its contents.

struct stat st;
if (fstat(fd, &st) == 0)
  printf("links=%d\n", st.nlink);
