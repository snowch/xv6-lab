Locks protect shared kernel state

Connect correct pipe byte accounting with a protected kernel critical section.

The children have separate user variables, but their inherited descriptors refer to one shared kernel pipe. Both writers update the pipe’s buffer and write counter; the reader updates its read counter.

A lock protects a critical section: operations on shared state that must be coordinated. pipewrite acquires the pipe lock before its loop, updates the buffer and counter while holding it, and releases it afterwards. A full-buffer wait releases the lock while sleeping so a reader can make space.

The example uses two writers and a reader, closes unused ends, reads until EOF and collects both children. Count the actual bytes rather than assuming a particular writer order. This connects process lifetime, descriptors, streams and scheduling with the shared kernel data behind them.

C reminder: assignment inside a loop condition

The parenthesised assignment first stores the read result in n. The > 0 comparison then decides whether to enter the loop. Use only the n bytes actually returned; a request for a larger count does not promise that many bytes arrived.

while ((n = read(fd, buf, sizeof(buf))) > 0) {
  /* consume buf[0] through buf[n - 1] */
}
