Boot prepares the first user process

Find the first runnable process before the scheduler starts executing it.

Compiler and kernel run locally.
Your source stays in this browser.

userinit creates the first process rather than loading every user program at boot. It allocates a process record and user page table, copies a tiny initcode program into user memory, and prepares a saved user PC of 0 and an initial stack pointer.

After recording its name and root directory, userinit marks the record RUNNABLE. It has prepared execution; the CPU is still in kernel main. The observation runs at exactly that boundary, before main calls scheduler. Build and expect one runnable process.

When selected, the process reaches the first return-to-user path. initcode requests exec of /init; init opens the console and starts the shell. The shell later starts workbench. Those are successive processes and program replacements, not extra tasks magically provided by the browser.

C reminder: loops and bounds

The initialiser runs once, the condition is checked before each iteration, and i++ advances the index afterwards. With i < count, the visited indices are 0 through count - 1. The array must have enough elements for those accesses.

for (int i = 0; i < count; i++) {
  /* use element i */
}
