The buffer cache reuses a block’s identity

Observe a cached buffer without confusing its address with a disk block number.

Compiler and kernel run locally.
Your source stays in this browser.

bread returns a locked cache buffer for a device and block number. bget finds an existing identity or recycles an unreferenced buffer; bread reads the device only if that buffer is not valid.

This controlled probe releases the superblock buffer, then requests the same block again. Build and observe the same cache object. Request block 2 instead to obtain a different identity. Comparing these fixed cache-object addresses does not grant permission to keep using a released buffer.

brelse drops the reference and moves an unused buffer to the most-recently-used end of the list. bget searches from the opposite end when recycling. A live reference prevents that buffer from being recycled; the next lesson inspects that protection.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
