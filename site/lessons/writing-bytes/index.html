The kernel writes your bytes

See that write sends a specified number of bytes to an output.

The previous program used printf to format a message. Here we call directly. It asks the kernel to copy bytes to an open output.

In write(1, "hello\n", 6), 1 names this process’s standard output, the string supplies the bytes, and 6 is their count. The newline \n is one byte, so the six bytes are h e l l o and a newline.

The kernel’s sys_write handler obtains these arguments, then passes them to filewrite. For this run, standard output leads to the xv6 console.

C reminder: strings and byte counts

A C string is a character array ending with a zero byte. The newline escape \n is one byte. A byte-counted write uses the count you pass; it does not search for the string terminator.

char text[] = "hello\n";
// Six message bytes, followed by one zero terminator.

What this shows

        
The kernel follows the byte count you pass. A C string’s terminator does not decide how many bytes write sends.
