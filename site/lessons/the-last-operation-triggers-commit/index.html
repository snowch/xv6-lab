The last outstanding operation triggers commit

Observe pending changes before and after the final end_op.

Compiler and kernel run locally.
Your source stays in this browser.

A transaction can contain updates from several overlapping filesystem operations. end_op decrements outstanding. Only the last completion sets committing and runs commit; earlier completions leave the recorded block list pending.

This controlled probe begins two operations and modifies one actual file block. It ends one operation, samples whether the log still has entries, and then completes the remaining operation. Build and observe pending before cleanup=1. The final cleanup commits Z, which the supplied program reads back.

Set FINISH to 2 to complete both operations before the sample. The real commit installs the data and clears the in-memory log count, so pending becomes 0. The loops still call end_op exactly twice. Returning from a particular syscall and defining a transaction boundary are related through this protocol, not through a one-syscall-one-transaction rule.

C reminder: loops and bounds

The initialiser runs once, the condition is checked before each iteration, and i++ advances the index afterwards. With i < count, the visited indices are 0 through count - 1. The array must have enough elements for those accesses.

for (int i = 0; i < count; i++) {
  /* use element i */
}
