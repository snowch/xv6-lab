The log absorbs repeated updates to one block

Observe that a repeated log_write does not add another pin.

Multiple changes to one disk block need only one log entry containing its final cached contents. log_write searches for an existing block number before appending a record. The first entry pins the buffer; another call for the same block does not pin it again.

The supplied program creates a file containing A. The edited kernel hook changes its actual data byte to Z and records it twice. The console reports the reference-count change and the byte read after commit.

The alternate path uses a manual bpin in place of the repeated log_write. The measured extra reference becomes 1; the paired bunpin removes it before normal completion. This comparison exposes absorption’s reference effect without leaking a buffer or changing the journal’s block list.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
