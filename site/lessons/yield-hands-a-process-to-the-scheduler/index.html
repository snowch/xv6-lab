Yield changes state before switching away

Observe the runnable-to-running transition around a real context switch.

yield does not choose the next process. It acquires the current process’s lock, marks that process RUNNABLE, and calls sched to switch to the CPU scheduler’s context. The scheduler searches for a runnable process, marks the chosen one RUNNING, and switches into its saved context.

The editable yield is the actual routine. A supplied getpid lab hook calls yield explicitly, so the observation does not depend on timer timing. The observation is restricted to workbench and runs just before sched, when its state is RUNNABLE.

The call to sched returns only once this process has been scheduled again. At that point the scheduler has marked it RUNNING, so the same test reports 0. Scheduling is not a direct jump from one user program into another: it passes through the per-CPU scheduler.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
