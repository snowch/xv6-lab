An indirect block extends a file’s block map

Follow the transition from the last direct pointer to an indirect entry.

Compiler and kernel run locally.
Your source stays in this browser.

A file byte offset first becomes a logical block index and an offset within that block. bmap translates the logical index to a physical disk block. The first twelve entries are direct pointers stored in the inode.

The next inode slot points to a block containing 256 more block numbers. For logical index 12, bmap subtracts NDIRECT and reads entry zero from that indirect block. With 1024-byte blocks, this version supports 268 data blocks per file; the indirect table itself also consumes disk space.

The supplied program prepares thirteen data blocks. Build with logical=11 to match the inode’s last direct pointer. Select 12 to obtain a different physical block through the actual indirect lookup. The table remains present in both runs. bmap can allocate missing blocks, but this fixture has already populated both paths.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
