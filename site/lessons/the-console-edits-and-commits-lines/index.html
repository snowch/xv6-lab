The console edits a line before readers consume it

Observe real console-buffer editing and newline commitment.

The UART input handler obtains bytes from the device and passes them to consoleintr. The console adds a line-oriented policy: it tracks read, committed-write and edit positions, supports editing keys, and wakes readers when a line is committed.

This kernel lab hook feeds an explicit sequence directly into the real consoleintr callback to isolate line editing from interrupt delivery. It does not emulate a physical keyboard event. The supplied user program then calls read on its actual console descriptor and prints the bytes from the kernel’s buffer.

The sequence types cat, sends Ctrl-U (0x15), then types dog and a newline. Ctrl-U removes the unfinished line, so the first run returns dog and a newline. Backspace instead removes just one unfinished character, leaving ca before dog. The newline advances the committed boundary so the waiting read can finish.

C reminder: an array of character codes

An int array can hold printable character codes and numeric control codes. '\n' is one newline character; 0x15 is hexadecimal for decimal 21. The array’s length comes from its initializer here, and index 0 names its first element. This is a sequence of integer codes, rather than a zero-terminated string.

int keys[] = {'a', 0x15, 'b', '\n'};
