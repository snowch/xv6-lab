A guard page catches an invalid user access

Connect a cleared U bit with a real, contained user page fault.

Compiler and kernel run locally.
Your source stays in this browser.

exec allocates two pages for the initial stack region and clears U on the lower page. That page remains backed by physical memory, but user-mode access is denied. It is a guard page, intended to catch a stack that grows beyond its allowed page.

This lesson deliberately changes getpid’s result into a lab address. The handler locates the guard page below the saved user stack pointer and reports its real V and U bits. The supplied test program forks a child, has it load a byte from the returned address, and lets the parent collect its status. The handler’s return value is no longer a PID in this experiment.

Build and find guard valid=1 user=0, a user page-fault report and child status -1. The parent and shell continue. Changing the returned address to the adjacent usable stack page lets the child complete. volatile ensures the test actually attempts its load; it does not make a protected address valid.

C reminder: casts, dereferences and volatile

The cast converts an address value to a pointer type. The leading * then performs the memory access. volatile requires this read to occur, but it does not grant permission to the address or make an invalid access valid. The experiment confines that deliberate access to a child process.

volatile char value = *(volatile char*)address;
