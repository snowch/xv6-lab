The kernel maps RAM and device registers

Observe an identity mapping and distinguish executable text from device memory.

Compiler and kernel run locally.
Your source stays in this browser.

A kernel often needs stable access to physical RAM and device registers. xv6 directly maps its kernel RAM: a virtual address in that region translates to the same numerical physical address. This is an identity mapping, not an absence of translation.

The kernel also maps memory-mapped I/O, or MMIO. Reads and writes at those physical addresses communicate with devices rather than ordinary RAM. UART0 names the console device’s register region. Merely reading its PTE does not access a UART register.

Build with KERNBASE. The mapping should be an identity mapping, read-only and executable. Then query UART0: it is also mapped at its physical address, but is writable and not executable. Other mappings, including the high trampoline, deliberately use different virtual and physical addresses.

C reminder: extracting fields with shifts and masks

Right shift discards low bits, and bitwise & keeps the bits selected by a mask. 0x1ff has nine low bits set; 4095 has twelve. A cast to int makes these small extracted values suitable for printf’s %d argument.

int index = (int)((va >> 12) & 0x1ff);
int offset = (int)(va & 4095);
