Initialized records are not running processes

Distinguish preparing the process table from allocating and scheduling a process.

The kernel reserves a fixed array of process records. Zero-initialized records start in UNUSED, whose enum value is zero. procinit initializes each record’s lock and kernel-stack address; it does not start NPROC programs.

The inserted loop reads the table immediately after procinit, before userinit creates the first process. On this single-hart boot path, no scheduler is running another process concurrently. The constant NPROC is the number of available slots, 64 in this build.

Later allocproc claims an unused record, and userinit makes the first prepared process RUNNABLE. Still later the scheduler selects a runnable record and changes it to RUNNING. Initialization, allocation, eligibility and execution are four different events.

C reminder: loops and bounds

The initialiser runs once, the condition is checked before each iteration, and i++ advances the index afterwards. With i < count, the visited indices are 0 through count - 1. The array must have enough elements for those accesses.

for (int i = 0; i < count; i++) {
  /* use element i */
}
