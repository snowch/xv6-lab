The trampoline has a shared virtual location

Compare the actual trampoline and trapframe mappings across user and kernel page tables.

Compiler and kernel run locally.
Your source stays in this browser.

The trampoline is a page of assembly used when crossing between user and kernel execution. Its instructions have to remain reachable while the active page table changes. xv6 maps that page at the same high virtual address in both page tables, referring to the same physical code.

Build and compare the real entries: both should be valid, both should identify the same physical frame, and the user page table’s entry should have U cleared. The CPU uses this mapping while in supervisor mode; user programs cannot execute it directly.

The trapframe has a different arrangement. It is mapped just below the trampoline in the user page table, also without U. Under the kernel page table, the kernel accesses its physical allocation through the direct RAM mapping, rather than through the TRAPFRAME virtual address. The next chapter follows how the trampoline saves registers there.

C reminder: bit masks and short-circuit checks

The bitwise & operator selects flag bits. A selected flag can have a value such as 16, so compare with zero when you want a printed 0 or 1. Logical && evaluates its right side only if the left side is true; entry && (*entry & PTE_V) therefore avoids dereferencing a null pointer.

int user = (flags & PTE_U) != 0;
int valid = entry && (*entry & PTE_V);
