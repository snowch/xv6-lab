A failed exec leaves the caller running

Handle exec returning -1 when it cannot load the requested program.

Compiler and kernel run locally.
Your source stays in this browser.

The file named missing is not present in this fresh xv6 filesystem. cannot load it, so it returns -1. The caller continues with its existing program and memory.

That is why the printf after exec is useful error handling: it is reached when exec fails. On success, the replacement program starts instead. The line after a successful exec is not a place to put work that the replacement should perform.

Build the unchanged example. You should see exec result=-1 and the same caller PID before and after the failed request. The local variable before is still available because the old program was not replaced.
