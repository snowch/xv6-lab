Wakeup makes a process runnable

Connect a pipe condition change with the scheduler’s runnable state.

Compiler and kernel run locally.
Your source stays in this browser.

A sleeping process has a channel identifying the condition it is waiting for. In the pipe example, readers wait on an address associated with the read counter.

After a producer changes the pipe, it calls wakeup on that channel. The kernel marks matching sleeping processes RUNNABLE. This makes them eligible for scheduling; it does not immediately transfer the CPU to every awakened process.

The reader checks its pipe condition again when it runs. A condition loop remains necessary because a wakeup signals possible progress, and another reader could consume data first.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
