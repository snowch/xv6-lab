Runnable processes take turns

Observe progress by two child processes without assuming an exact output order.

Compiler and kernel run locally.
Your source stays in this browser.

A runnable process is eligible to use the CPU. A running process is the one currently using it. xv6’s scheduler searches its process table for runnable work, switches to a saved kernel context, and regains control when the process blocks or yields.

Two children each write a single-byte label three times, sleeping between writes. Their progress shares one emulated CPU. The output can contain different arrangements of A and B; the interface promises neither an exact alternation nor a fixed scheduling delay.

The parent collects both children. Each child’s ordinary variables are private, while the scheduler manages their separate saved contexts and states.

C reminder: loops and bounds

The initialiser runs once, the condition is checked before each iteration, and i++ advances the index afterwards. With i < count, the visited indices are 0 through count - 1. The array must have enough elements for those accesses.

for (int i = 0; i < count; i++) {
  /* use element i */
}
