The loader supplies zero bytes for BSS

Change actual page initialization before loading a native NOBITS object.

C requires an uninitialized object with static storage to start at zero. For a native ELF BSS region, those bytes are absent from the file. xv6 satisfies the requirement by zeroing allocated pages before copying each segment’s file-backed bytes over the prefix.

The editable uvmalloc is the actual allocator. The supplied workbench program execs native bssprobe, whose source is available below. Its volatile array read forces an actual memory load. The native program reports the array byte it actually reads.

Only allocations while the caller is named workbench receive that fill, isolating this exec experiment from normal init and shell loading. The file copy does not overwrite BSS, so the native program reads 7. This deliberately violates the initialization contract. It does not use a browser link-slot global as evidence of ELF zero-fill.

C reminder: array storage and compile-time sizes

enum supplies an integer constant usable as an array size. A static local array has storage lasting for the process, rather than living in this function’s call stack. static does not make user memory shared between separate processes or preserve it across a fresh run.

enum { N = 6000 };
static char data[N];
