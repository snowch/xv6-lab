A copy must check each page it crosses

Observe a checked copy stopping at an unmapped boundary after copying an initial byte.

Adjacent virtual pages need not be adjacent physical pages, and the second page may not be mapped at all. copyin therefore copies at most the remaining bytes in one page, then translates the next virtual page before continuing.

The supplied program has not grown a heap. Its stack’s upper boundary is followed by an unmapped page. The source starts at the last byte of the stack and requests two bytes. The console prints the result and tracks which of the two destination bytes changed.

The first byte can already have been copied before the second page fails. A -1 return does not promise that the destination buffer is untouched. Callers must check the result and follow the interface’s error contract. The loop’s page-by-page work is also what lets successful copies span noncontiguous physical pages.

C reminder: array initializers and comparisons

char bytes[2] reserves two elements, indexed 0 and 1. The initializer gives each the value 7, so later comparisons can detect which elements changed. != compares values; it does not assign. These are raw bytes, with no C-string terminator implied.

char bytes[2] = {7, 7};
int changed = bytes[0] != 7;
