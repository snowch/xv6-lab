A suspended kernel thread has its own stack

Locate the real saved kernel stack pointer after a scheduling round.

A process has a user stack and a separate kernel stack. Traps switch to the kernel stack before entering kernel C. A process blocked inside read or wait retains its kernel call frames while another process runs.

The probe calls the actual yield routine. Its path through sched and swtch saves p->context.sp. When this process is scheduled again, those kernel frames resume and the probe checks the saved address against its own kernel-stack page.

Selecting the trapframe’s sp instead reads the saved user stack pointer, which is outside this kernel-stack mapping. Neither saved field is a claim to read the CPU’s current live sp at this line.

C reminder: addresses and integer casts

In this RV64 kernel, uint64 holds 64-bit values, including its address values. The cast converts a pointer to that integer type for a byte-offset calculation. Adding 4096 to this integer advances by 4096 bytes; adding to a typed pointer would instead count its element size. This calculation does not allocate storage or change the CPU’s stack pointer.

uint64 base = (uint64)stack0;
uint64 top = base + 4096;
int offset = (int)(top - base);
