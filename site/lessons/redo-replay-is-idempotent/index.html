Lesson 6 of 6 in Chapter 14

Redo replay can be repeated safely

Install the same committed block image twice before clearing the header.

A crash may interrupt recovery itself. The journal cannot depend on remembering which home blocks were already installed in the previous boot. Instead, copying a committed final block image is idempotent: copying it again leaves the same bytes.

This page uses the same prepared O-to-R committed journal. The edited recovery loops over the actual install_trans routine before clearing its header. The console reports the number of actual installation passes and the byte read by the user program.

This property would not follow from replaying an arbitrary instruction such as “increment this byte.” A redo log stores the desired block image, and the committed header remains available until installation is complete. Clearing it is safe only after every recorded image has reached its home location.

C reminder: loops and bounds

The initialiser runs once, the condition is checked before each iteration, and i++ advances the index afterwards. With i < count, the visited indices are 0 through count - 1. The array must have enough elements for those accesses.

for (int i = 0; i < count; i++) {
  /* use element i */
}
