A failed exec preserves the old image

Observe failure returning to the caller with its old memory intact.

Building a new image can fail while reading headers, allocating pages or copying arguments. xv6 constructs a candidate page table while retaining the old one. Only after successful preparation does it assign p->pagetable and free the previous image.

The bad path frees any candidate image and releases the executable inode and filesystem operation. The original program can then receive -1 from exec and handle the failure.

The program creates a text file and tries to execute it. A canary is a known value the probe checks after the operation. Here it checks that the old program’s variable remains accessible after the failed replacement. A successful exec would enter a new program instead of returning to this printf.

C reminder: arguments and return values

A call such as f(x) passes an argument to a function. return supplies its result. In a nested call, the inner result becomes an argument to the outer call; assigning the result to a variable can make that easier to read.

printf("reported pid=%d\n", pid);
