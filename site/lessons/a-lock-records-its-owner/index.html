A spinlock records its owning CPU

Distinguish a set lock word from this CPU’s ownership of it.

Compiler and kernel run locally.
Your source stays in this browser.

The lock word answers whether a lock is held. xv6 also records the owning CPU in lk->cpu. holding checks both fields; release rejects a caller that does not own the lock.

The probe acquires a real local spinlock, samples ownership, releases it and samples again. holding requires interrupts off so the CPU lookup stays stable, which is why the second sample has an explicit push_off/pop_off pair. The first sample already has interrupts disabled by acquire.

Build and expect 0 from the after sample. Select before to observe 1. This is CPU ownership for a spinlock, not the process PID ownership used by a sleeping lock.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
