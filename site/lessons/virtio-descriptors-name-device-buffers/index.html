Descriptors tell the device which memory to use

Read the actual request direction and device-write flag in a submitted VirtIO chain.

Compiler and kernel run locally.
Your source stays in this browser.

A VirtIO block request uses three linked descriptors: one for the request header, one for the data buffer, and one for the status byte. Each descriptor contains an address, a length, flags and a next index. The available ring publishes the chain’s first index to the device.

Direction has two perspectives. Reading the disk requires the device to write into the RAM buffer, so the data descriptor has VRING_DESC_F_WRITE set. Writing the disk requires the device to read the RAM buffer, so that flag is clear. This descriptor flag is separate from CPU page-table permissions.

The editable free_chain observes the real completed chain just before it is recycled. A source-visible native accessor returns the actual descriptor-array pointer; it bridges the browser compiler’s large-global-address limitation. A temporary getpid hook arms and disarms the observer; it still returns the real PID. Build and observe request write=0 device writes data=1 for actual reads. The supplied program also causes writes, which the alternate filter observes.

C reminder: pointers and the -> operator

For a pointer p to a struct, p->pid means (*p).pid: follow the pointer, then read its pid member. Use the dot operator with a struct value itself. Reading a member and assigning to it are different operations.

p->pid        // read a member through a pointer
p->pid = 7;   // assign a new member value
