A page-table walk follows physical page addresses

Read the real entries along a mapped user address’s translation path.

The process record points to its top-level page table. A valid branch entry identifies the physical page containing the next table. A leaf entry identifies the physical page containing the program’s bytes and carries access permissions.

The observation follows the same indices and PTE2PA conversion used by walk, reading actual entries without allocating anything. A set V bit marks a valid entry. R, W or X marks a leaf; an intermediate entry has V set without those permission bits.

Address 0 contains the supplied program’s code. The kernel can read the table pages through its direct mapping of physical RAM. A missing intermediate entry would stop this read-only inspection; walk’s alloc argument separately controls whether the real kernel routine may create missing tables.

C reminder: array entries versus their addresses

table[index] reads an entry through a pointer. &table[index] instead gives the address of that entry, so a function can return it or change it. p->pagetable first reads a member of the process struct; that member’s value is itself a pointer to a table.

pte_t value = table[index];
pte_t *address = &table[index];
